# Голосовые заметки

Запись голоса с микрофона и расшифровка в текст — локально, на своём
компьютере. Интернет нужен один раз, чтобы скачать модель распознавания;
дальше всё работает офлайн.

Записи складываются в папки-блоки, расшифровки лежат рядом обычными `.txt`.
Никакой базы и закрытых форматов: всё, что записано, можно открыть блокнотом
и перенести куда угодно.

## Что умеет

**Запись**

- Запись с любого микрофона, который видит Windows
- Пауза и продолжение без разрыва файла
- Отмена последней записи: на диск ничего не попадает
- Индикатор уровня звука и таймер на лету
- АвтоСтоп: запись останавливается сама, когда вы замолчали
- Запись не копится в памяти — хоть час, хоть ночь

**Расшифровка**

- Распознавание речи моделью Whisper, локально, без интернета
- Автоматическая расшифровка сразу после остановки записи
- Копирование готового текста в буфер обмена
- Разбивка на абзацы по паузам в речи
- Необязательные метки времени вида `[00:12]`
- Отмена распознавания в любой момент — без обрезанного текста на диске

**Записи**

- Блоки: каждая тема в своей папке, в таблице только текущий блок
- Правка текста прямо в окне с записью обратно в файлы
- Открытие файлов двойным щелчком: звук — проигрывателем, текст — блокнотом
  (точнее, программой по умолчанию для этого расширения)
- Смена корневой папки записей без переноса файлов
- Понятная строка состояния: жёлтый — работа идёт, зелёный — готово,
  красный — ошибка

## Требования

- **Windows** (приложение использует WASAPI, реестр устройств и `winsound`)
- **Python 3.14** — версия закреплена в `pyproject.toml` (`>=3.14,<3.15`)
- **[Poetry](https://python-poetry.org/) 2.0 или новее** — проект описан
  по PEP 621, а Poetry 1.x такой `pyproject.toml` не читает и затирает
  `poetry.lock`
- **Около 1,5 ГБ свободного места** под модель `medium`. Если в Windows
  выключен режим разработчика, файлы модели дублируются и нужно до 3 ГБ —
  приложение предупредит об этом при первом запуске

Видеокарта не нужна: распознавание идёт на процессоре в режиме `int8`.
Ориентир по скорости на машине разработчика: запись длиной 40 секунд
модель `medium` разбирает примерно за 16 секунд.

## Установка и запуск

```bash
poetry install
poetry run python main.py
```

При первом запуске приложение скачает модель. Перед загрузкой оно показывает
уведомление: что именно скачивается, в какую папку, каким способом хранятся
файлы и сколько места это займёт. Пока идёт загрузка, строка состояния
показывает проценты, скорость и оценку остатка:

```
Скачиваю модель «medium»: 45% (640 МБ из 1,5 ГБ), 8,2 МБ/с, осталось ~2 мин
```

Пока идёт загрузка, приложением можно пользоваться как обычно: запись
работает, а распознавание начнётся, когда модель будет готова.

Когда файлы докачаны, модель читается с диска в память — этот этап тоже
занимает время, о нём сообщает счётчик секунд. После загрузки приложение
сообщает итоговый размер и что интернет больше не нужен.

## Как пользоваться

1. **Назовите блок.** Введите название в верхнее поле и нажмите Enter.
   В подсказке поля виден полный путь, куда попадут записи. Пустое название —
   записи уйдут в папку `без названия`.
2. **Начните запись** кнопкой **▶**. Она же ставит паузу и продолжает:
   значок меняется на **❚❚**, пока идёт запись, и обратно.
3. **Остановите** кнопкой **■** — файл сохраняется. Кнопка **✕** отменяет
   запись целиком: на диск ничего не попадёт.
4. **Распознайте.** Если включено «Распознавать после остановки», расшифровка
   начнётся сама. Иначе нажмите **Распознать**: будет расшифрована последняя
   запись текущего блока без текста. Повторное нажатие прерывает распознавание.
5. **Поправьте текст** в окне и нажмите **Сохранить** — правки уйдут в файлы
   `.txt`. Есть также «Сохранить как» для отдельного файла.

> Пока идёт распознавание, кнопка записи погашена: одновременно писать
> и распознавать нельзя — модель не потокобезопасна.

Пока модель загружается в память, кнопка **Распознать** тоже погашена —
подсказка объясняет почему. Записывать при этом можно как обычно, и если
включено «Распознавать после остановки», запись не останется без текста:
расшифровка начнётся сразу после загрузки модели.

Вторая зона с таблицей и текстом свёрнута при запуске. Открывается кнопкой
справа в строке управления; окно подрастает под неё анимацией. Сама по себе
зона не открывается даже после распознавания: результат ждёт, когда вы
нажмёте кнопку. Таблица при этом уже прокручена к последней записи, а новый
кусок текста показывается сам — ползунок уходит к нему, не дожидаясь, пока
его потянут руками.

Записи, положенные в папку блока вручную, появляются в таблице после Enter
в поле названия или после переключения блока: отдельной кнопки «Обновить» нет.

## Настройки

Четыре галочки и АвтоСтоп спрятаны в меню кнопки **«Настройки»** — она стоит
в строке управления. Всё включено при первом запуске, дальше выбор
запоминается.

| Настройка | Что делает |
|---|---|
| **Распознавать после остановки** | После **■** запись сама уходит в расшифровку. Если модель ещё грузится, распознавание начнётся, как только она будет готова |
| **Копировать в буфер** | Готовый текст сразу попадает в буфер обмена — только что распознанная запись, а не всё окно |
| **Таймкоды** | Метки вида `[00:12]` в начале строк и заголовок с датой на полосе между записями |
| **Звук после распознавания** | Короткий сигнал по окончании расшифровки |
| **Автостоп** | Остановить ли запись по тишине: `нет`, 3, 5 или 10 секунд |

С включёнными «Распознавать» и «Копировать» сценарий сокращается
до «записал → нажал ■ → вставил».

Настройки пишутся в файл сразу при переключении. Блок, микрофон и модель
запоминаются при закрытии окна.

## АвтоСтоп

Говорите, замолчали — запись останавливается сама. Срок выбирается в меню
«Настройки → Автостоп», по умолчанию пять секунд. Перед остановкой в строке
состояния появляется предупреждение «Тишина — остановлю запись», чтобы запись
не обрывалась незаметно.

**Автостоп ждёт первой фразы.** Если нажать **▶** и ещё ничего не сказать,
запись не оборвётся через пять секунд, пока вы собираетесь с мыслями:
приложение подождёт и покажет «Микрофон молчит — запись ждёт первой фразы».
Останавливать запись, в которой человек ещё не сказал ни слова, значило бы
отменять её раньше времени.

Тишина считается по среднеквадратичному уровню звука, а не по пику: одиночный
щелчок мышью пиком выглядит громко, а средним уровнем — нет. Между порогами
`SILENCE_FLOOR` и `VOICE_LEVEL` лежит мёртвая зона, чтобы шум на границе
не заставлял таймер дрожать. Пороги замерены на машине разработчика: фон
в комнате держится около `0.004`, речь — от `0.03`. В шумной комнате их
придётся поднять.

Пауза тишиной не считается: пока запись на паузе, отсчёт не идёт, а после
продолжения начинается заново.

**Запись из одной тишины не сохраняется.** Если микрофон молчал всё время,
файла не будет, а в строке состояния появится «Отсутствуют входные данные,
запись отменена».

В сохранённой записи тишина по краям остаётся: обрезка отрезала бы часть
записи, а лишние секунды молчания и так убирает фильтр речи при распознавании.

## Таймкоды и чистый текст

Таймкоды — это две вещи сразу: метки `[00:12] ` в начале строк расшифровки
и заголовок с датой на полосе между кусками. Они полезны, когда правят
записи в окне: видно, где что сказано. В готовом тексте, который уходит
в чужую программу, они мешают, поэтому настройку можно выключить — новые
расшифровки придут уже без меток.

Граница между кусками видна в окне всегда: это серая полоса. С включёнными
таймкодами на ней стоит заголовок вида `── 13.10.2026 21:00:31 · идея ──`,
с выключенными — только полоса, без единого символа. Перед полосой стоит
пустая строка, иначе конец одной записи и начало следующей читаются как один
поток.

В файлы `.txt` и в буфер обмена ни полоса, ни дата не попадают — там только
речь. Кнопка «Скопировать в буфер» вырезает заголовки разделителей, даже
если таймкоды включены. Границы записей при этом никуда не деваются: они
лежат в оформлении окна, поэтому правка текста не сдвигает их и не путает
куски между собой.

Абзацы внутри одной записи появляются там, где человек молчал дольше двух
секунд.

## Список записей

Таблица показывает только текущий блок. Колонки: папка, файл, текст,
длительность и размер. Порядок хронологический — старые сверху, свежие снизу,
и окно само прокручивается к последней записи.

- **Двойной щелчок по имени файла** открывает `.wav` — обычно проигрывателем
  Windows.
- **Двойной щелчок по колонке «Текст»** открывает `.txt` — обычно Блокнотом.
- Колонка «Текст» показывает имя файла расшифровки, а если её ещё нет —
  серое «Нет текста».

Оба файла открываются программой по умолчанию для этого расширения.

**Сменить папку…** работает в двух случаях:

- выбрана папка блока внутри корня записей — приложение переходит в этот блок;
- выбрана папка снаружи — она становится новым корнем для записей.

Так сделано намеренно: иначе папку блока можно было выбрать по ошибке,
и блоки начинали вкладываться друг в друга (`recordings/идея/идея`).
Если выбрать папку внутри корня, но не сам блок, приложение спросит
подтверждение.

## Строка состояния

Цвет сообщения внизу говорит, что сейчас происходит.

| Цвет | Когда |
|---|---|
| жёлтый | работа идёт: запись, сохранение, распознавание, загрузка модели |
| зелёный | готово: записано, распознано, сохранено, файл открыт |
| янтарный | предупреждение — например, «Работающих микрофонов не найдено» |
| красный | ошибка: запись не началась, файл не открылся, модель не загрузилась |
| серый | обычное сообщение, ни к чему не обязывает |

Пока модель грузится, сообщение о загрузке не перебивается обычными строками
статуса — иначе оно мелькнуло бы и пропало. Предупреждения и ошибки его
перебивают.

## Где что лежит

```
recordings/                     ← корень записей, рядом с программой
  линтер/                       ← папка блока
    2026-10-11_00-42-29.wav     ← запись
    2026-10-11_00-42-29.txt     ← расшифровка к ней
```

Корень записей создаётся рядом с исполняемым файлом (или рядом с `main.py`
при запуске из исходников). Поэтому приложение можно скопировать в другую
папку вместе с записями — или без них, тогда `recordings/` появится заново.

Настройки и служебные файлы — в профиле пользователя:

```
%APPDATA%\SmartVoiceRecorder\settings.json     ← настройки
%APPDATA%\SmartVoiceRecorder\crash.log         ← необработанные ошибки
%APPDATA%\SmartVoiceRecorder\model-load.log    ← лог загрузки модели
%LOCALAPPDATA%\SmartVoiceRecorder\models\      ← скачанная модель
```

Путь не зависит от того, откуда запущено приложение: из ярлыка, из bat-файла
или из редактора — файлы те же.

## Настройки вручную

`settings.json` — обычный JSON, его можно править текстовым редактором.
Неизвестные поля игнорируются, отсутствующие берут значения по умолчанию,
испорченный файл не мешает запуску.

```json
{
  "recordings_dir": "C:/путь/к/записям",
  "model": "medium",
  "microphone": 14,
  "last_block": "линтер",
  "auto_transcribe": true,
  "auto_copy": true,
  "timecodes": true,
  "play_sound": true,
  "auto_stop_seconds": 5
}
```

| Поле | Что значит |
|---|---|
| `recordings_dir` | Корень записей |
| `model` | `tiny`, `base`, `small` или `medium` |
| `microphone` | Номер устройства, `null` — выбрать автоматически |
| `last_block` | Название блока, подставленное в поле при запуске |
| `auto_transcribe` | Распознавать автоматически после остановки записи |
| `auto_copy` | Копировать распознанный текст в буфер обмена |
| `timecodes` | Метки `[00:12]` в начале строк и заголовок с датой на полосе между записями |
| `play_sound` | Короткий сигнал после распознавания |
| `auto_stop_seconds` | Сколько секунд тишины считать концом записи: `3`, `5`, `10` или `null` (автостоп выключен). Значение вне списка заменяется на `5` |

Старый формат с отдельной галочкой `auto_stop` читается как раньше:
`"auto_stop": false` означает выключенный автостоп.

## Модель распознавания

Используется [faster-whisper](https://github.com/SYSTRAN/faster-whisper) —
локальная реализация Whisper. Язык распознавания закреплён в коде: русский
(`LANGUAGE = "ru"` в `src/transcriber.py`).

| Модель | Размер на диске | Когда выбирать |
|---|---|---|
| `tiny` | ~75 МБ | быстро, качество среднее |
| `base` | ~145 МБ | чуть лучше `tiny` |
| `small` | ~460 МБ | разумный компромисс |
| `medium` | ~1,5 ГБ | рекомендуется: на русском заметно точнее |

Модель скачивается один раз и лежит в `%LOCALAPPDATA%\SmartVoiceRecorder\models`.
Это не общий кэш Hugging Face: кэш выглядит одноразовым, его могут очистить,
а модель должна переживать чистку и переезд проекта. Если модель уже была
скачана в старый кэш (`%USERPROFILE%\.cache\huggingface\hub`), при первом
запуске она переедет в новое место сама — качать заново не придётся.

Смена модели в списке **применяется при следующем запуске**: новая модель
может быть ещё не скачана, а её загрузка идёт минутами. Строка состояния
скажет об этом прямо:

```
Модель «small» применится при следующем запуске (сейчас работает «medium»)
```

**Без симлинков модель занимает вдвое больше.** Симлинки в Windows доступны
только в режиме разработчика или от администратора. Если режим выключен,
Hugging Face копирует файлы, и `medium` занимает около 3 ГБ вместо 1,5 ГБ.
Вернуть место можно, включив режим разработчика и удалив папку модели: она
скачается заново, уже без копий.

## Сборка в один файл

```bash
poetry run pyinstaller SmartVoiceRecorder.spec
```

Готовый файл — `dist\SmartVoiceRecorder.exe`, около 127 МБ. Python на целевой
машине не нужен. Модель распознавания (1,5 ГБ) в сборку **не входит**:
приложение скачивает её само при первом запуске, как и версия из исходников.

В спецификации вручную перечислены папки, которые PyInstaller не находит сам:

- `faster_whisper/assets` — модель фильтра тишины `silero_vad_v6.onnx` для
  `onnxruntime`. Без неё распознавание в собранном файле падает с `NO_SUCHFILE`;
- `src/assets` — значки интерфейса.

Если первый проход с фильтром тишины упадёт (например, файла фильтра нет
рядом), `src/transcriber.py` повторит расшифровку без него: медленнее
и шумнее на тихих записях, но работает.

### Значок приложения

Значок `.exe` берётся из `src/assets/icon.ico` — его указывает параметр
`icon=` в спецификации. Без этой строки PyInstaller вшивает свой значок,
и в Проводнике приложение выглядит чужим.

`.ico` собирается из исходного рисунка `src/assets/icon.png`:

```bash
poetry run python make_icon.py
```

Скрипт нарезает рисунок на размеры 16, 24, 32, 48, 64, 128 и 256 пикселей.
Один PNG в `.exe` не годится: мелкие размеры пришлось бы уменьшать на ходу,
и значок получился бы мыльным. Если рисунок меняется, `icon.ico` нужно
пересобрать, иначе в сборке останется старая картинка.

Тот же рисунок окно берёт и во время работы: `src/core/icons.py` читает
`icon.png` рядом с кодом, а в собранном файле — из распакованного архива
PyInstaller. Кроме того, приложение сообщает Windows свой AppUserModelID:
без этого панель задач группировала бы окно по процессу, и при запуске
из исходников там был бы значок Python.

Если после пересборки Проводник показывает старый значок, это его кэш:
он обновляется сам через некоторое время или после переименования файла.

## Устройство проекта

| Файл | Что в нём |
|---|---|
| `main.py` | Точка входа: ставит обработчик падений и запускает окно |
| `storage.py` | Где лежат записи: поиск, длительность, порядок, имена папок |
| `src/main_window.py` | Окно: кнопки, таблица, текст, строка состояния |
| `src/recorder.py` | Запись звука, микрофоны, пауза, автостоп, усиление |
| `src/transcriber.py` | Распознавание, отмена, разбивка на абзацы |
| `src/model_store.py` | Модель: скачивание, хранение, загрузка один раз |
| `src/widgets.py` | Индикатор записи и переливающаяся кнопка |
| `src/config.py` | Настройки и пути в профиле пользователя |
| `src/crash_log.py` | Запись необработанных ошибок в `crash.log` |
| `src/core/styles.py` | Всё оформление и цвета |
| `src/core/icons.py` | Загрузка значков из `src/assets` |
| `tests/` | Тесты: чистая логика и окно в offscreen-режиме |

Модули записи и распознавания ничего не знают про интерфейс и общаются
через колбэки — их можно вызывать из консоли и из тестов. Всё, что приходит
из рабочих потоков, попадает в интерфейс через сигналы `Signals`: Qt
разрешает трогать виджеты только из главного потока.

## Разработка

```bash
poetry install
poetry run ruff check .
poetry run ruff check --fix .
```

Правила линтера закреплены в `pyproject.toml`, а не берутся из умолчаний ruff:
иначе вердикт менялся бы сам при обновлении инструмента. Форматтер
`ruff format` не применяется — код написан так, как есть.

Тесты (без железа, только логика и окно в offscreen-режиме):

```bash
poetry run python -m unittest
```

Снимок в начале README пересобирается из настоящего окна:

```bash
poetry run python make_screenshot.py
```

## Особенности реализации

**Поток звука открывается в том потоке, откуда пришёл вызов.** WASAPI
не открывается из фонового потока и возвращает ошибку `-9999`. Поэтому
`Recorder.start()` зовётся из окна, а в своём потоке рекордер только ждёт
и сохраняет. По той же причине микрофоны проверяются по одному в главном
потоке: между проверками окно успевает перерисоваться.

**Частота записи 48 000 Гц, а не 44 100.** WASAPI отвергает 44 100.

**Микрофоны сравниваются с устройствами записи Windows, а не только между
собой.** У одного физического микрофона бывает несколько входов (WASAPI
и WDM-KS), а в списке он должен стоять один раз. Сравнивать имена целиком
нельзя: у всех устройств есть общие слова — «Microphone», «Audio», а в русской
Windows ещё «Микрофон», «звук», «аудио». Такие слова отбрасываются, иначе
все микрофоны сошлись бы в один.

**Устройство, которое открывается, но не отдаёт звук, отбрасывается.**
Устаревшие WDM-KS микрофоны и отключённые гарнитуры ведут себя именно так.

**Запись сохраняется громче микрофона.** Всё записанное умножается
на `RECORDING_GAIN` (1.3) в `src/recorder.py`. Усиливается сразу всё:
индикатор уровня, автостоп и файл считают уже усиленный звук. Громкий хлопок
вблизи микрофона при этом упрётся в потолок шкалы.

**Запись не копится в памяти.** Как только буфер набрал полминуты, он
дописывается в черновой `.raw` рядом с будущей записью. Поэтому даже часовая
запись держит в памяти десятки секунд звука. Буфер общий у двух потоков
(PortAudio пишет, сохраняльщик забирает), поэтому он защищён замком.

**Проценты распознавания не показываются.** Whisper молчит до конца первых
тридцати секунд звука, поэтому проценты прыгали с нуля сразу на семьдесят.
Вместо этого кнопка «Распознать» плавно переливается.

**Отмена распознавания ничего не пишет на диск.** Если прервали на середине,
файла `.txt` не будет. Так не появляется обрезанный текст, а запись можно
распознать заново.

**Пустая строка между записями — настоящий пустой блок.** `QPlainTextEdit`
рисует блоки вплотную, поэтому «воздух» перед полосой сделан отдельным пустым
блоком. В файлы записей он не попадает: кусок пишется от своего разделителя
до следующего, а переводы строк по краям срезаются.

**Сохранение защищено от потери текста.** Если кусок в окне оказался пустым,
а в файле текст есть, файл не перезаписывается: скорее всего, съехала
строка-разделитель. Исключение — окно очищено целиком: это осознанное
действие, и файлы очищаются вместе с ним. Ошибка записи одного файла не мешает
остальным и не роняет приложение — причина уходит в строку состояния.

**Загрузка модели в память видна.** Пока модель читается с диска, внизу окна
висит сообщение об этом, и другие строки статуса его не перебивают.

**Служебные сообщения Hugging Face скрыты.** Строки про токен и симлинки,
которые библиотека печатала при загрузке, убраны из консоли. На случай
разбора проблем лог загрузки всё равно пишется рядом с настройками.

## Ограничения

- Только Windows.
- Распознаётся только русская речь: язык закреплён в коде.
- Распознавание идёт на процессоре; видеокарта не используется.
- Одновременно можно либо писать, либо распознавать.
- Горячих клавиш нет — управление только кнопками.
- Модель скачивается при первом запуске; без интернета первый запуск
  не заработает.
- Если загрузка модели не удалась, повторить её можно перезапуском
  приложения: отдельной кнопки «Скачать заново» нет.
- Пороги тишины (`SILENCE_FLOOR`, `VOICE_LEVEL`) замерены на одной машине.
  В шумной комнате их, возможно, придётся поднять вручную.
- В собранном `.exe` тексты ошибок Qt остаются английскими, если в системе
  не установлен русский перевод Qt.
